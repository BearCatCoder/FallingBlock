# Design Change Workflow

## Purpose

Change gameplay or presentation intentionally before implementation.

## Sequence

1. Product Owner states the player problem, goal, non-goals, and priority.
2. Game Designer provides options, tradeoffs, edge cases, and recommendation.
3. QA Engineer defines observable acceptance scenarios.
4. Architect assesses architectural impact without implementation.
5. the project owner approves material scope or gameplay changes.
6. Product Owner updates the issue and `docs/GAME_DESIGN.md`.
7. Work Manager routes approved work into `issue-delivery.md`.

No Godot Engineer work begins until the decision and acceptance criteria are approved.
